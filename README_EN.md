# TBtools CLI

Run TBtools-II bioinformatics functions headlessly — from CLI, scripts, or AI agents.

**200+ plotting/analysis commands + 180+ RPC data tools + 80+ CLI tools + 110+ Java bridges + arbitrary engine reflection**, all verified to produce real output.

> **Numbers are machine-generated.** Run `tbtools version --json` (runtime) or see [docs/_generated/counts.md](docs/_generated/counts.md) (static registry, auto-generated to prevent drift).

## Why

Turn the 200+ tools of the GUI-only TBtools-II into a machine-callable interface:
discovery → describe → validate → execute → result → provenance, with structured JSON for AI agents.

## Install

```bash
pip install tbtools-cli          # PyPI (coming soon)
# or from source
git clone https://github.com/qby1613527176-cmd/tbtools-cli
cd tbtools-cli && pip install -e .
tbtools setup --auto             # locate or fetch the TBtools JAR
tbtools doctor                   # verify environment
```

> Requires Java (JRE 1.6 jar), Python 3.10+. On Linux, xvfb is needed for plotting.

## Quick Start

```bash
tbtools search "gene structure"                  # find a tool
tbtools tool-describe genestructure --json       # understand its schema
tbtools tool-validate genestructure g.gff ids.txt --json   # preflight check
tbtools seq structure g.gff ids.txt out.svg      # run it
tbtools tool-provenance out.svg                  # audit the run
```

Try with bundled examples: `examples/data/` (official data, reproducible).

## 🤖 Agent Interface (7 capabilities, all explicit)

| Capability | Command |
|---|---|
| 1 Discover | `tbtools search <task> --json` (multi-word / reverse `--input`/`--output` / capability) |
| 2 Describe | `tbtools tool-describe <cmd> --json` (schema: inputs/outputs/capabilities/dependencies/relations) |
| 3 Preflight | `tbtools tool-validate <cmd> <inputs...> --json` (existence/format/columns, `--force`) |
| 4 Execute | `tbtools tool-run <args...> --json` (pure-JSON stdout protocol, `--timeout`) |
| 5 Result | `tbtools tool-result <job_id>` / `job-status` (state machine) |
| 6 Status | `tbtools rpc status` / exit codes + TB error codes |
| 7 Provenance | `tbtools tool-provenance <output>` + `env --lock` |

**Async jobs**: `tool-submit` (background, `--timeout`) → `job-status` (`running → succeeded/failed/cancelled/timed_out`) → `job-log` → `job-result` → `job-cancel`.

**Error contract**: TB001–TB012 codes with `retryable` + `suggested_action`; failed runs also write provenance.

**AI machine layer** (`ai/`, generated by `gen_metadata --render`): tool-index.jsonl (294), capability-index, workflows (4), relations, per-tool schemas, error-codes.

## Architecture

```
Agent / CLI / Script
        │  JSON
┌───────▼────────┐   CommandSpec (single command model, 294)
│  Tool Registry │ ← ENGINE_REGISTRY + CLI_TOOLS + manual, projected to metadata
└───────┬────────┘
        ▼
  CLI Runner · RPC Runner (188 methods) · Job Runtime
        ▼
   TBtools-II JAR (Java engine / bridges / external tools)
        ▼
   Artifacts + Provenance (<output>.tbtools.json)
```

- `core.py` split: `errors.py` (error codes) + `runtime/java.py` (execution/input-protection/provenance)
- Input protection: engine side-effects on user files are snapshotted & restored
- 46+ documented pitfalls; bilingual hints (Chinese default, `--lang en`)
- Supply chain: `fetch-jar` records SHA256; `doctor` verifies it
