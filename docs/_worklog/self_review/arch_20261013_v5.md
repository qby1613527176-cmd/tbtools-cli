### P1

1. **(P1,GPT P1 增量核实成立)空指纹 `_fp_same` 违背证据身份不变量,且写读两端不对称**
   - **指纹不变量(从代码归纳)**:contract_fingerprint 在加载端(L1183-1190)与只读校验端(L472)均被当作**可空但空即无证据**——`not _old_fp → discard` / `assert 非空`;即"指纹非空"是证据身份的隐含前置不变量,只是没有集中声明。env_fingerprint 语义略弱:加载端只在**真值非空**时比对(`if _old_env:`),无 JAR 环境允许缺省(与写入端"无 JAR 不刷新"对称)。
   - **缺陷**:`_fp_same`(L405-408)只做相等性比较,无非空前缀。`"" == ""` → True,使继承判据 `_allow_conf = _old_conf and _gold != "fail" and _fp_same` 在**零证据**下成立。实机探针(#2)确认显式空串旧证据 + 金链 skip → 实际写出 CONFORMANCE_VERIFIED。
   - **对 fail/skip/pass 三态的影响**:fail 支路不受影响(`_gold=="fail"` 先短路降级,fp 不参与);pass 支路不受影响(`_gold=="pass"` 无条件升级,且 pass 时 fp 是新算的非空值);**只有 skip/None 继承支路被空指纹污染**——恰好是证据最弱、最需要守卫的支路。修复(加非空前缀)与 fail/pass 两态**正交**,无副作用。
   - **架构级修复建议**:`_fp_same` 前置非空条件,与加载端"缺 fp 即 discard"对齐:
     ```python
     _nc = _exec_entries.get(_t, {}).get("contract_fingerprint")
     _oc = _old_entry.get("contract_fingerprint")
     _fp_same = (bool(_nc) and bool(_oc) and _nc == _oc
                 and _exec_entries.get(_t, {}).get("env_fingerprint")
                     == _old_entry.get("env_fingerprint"))
     ```
     contract_fp 要求**双侧非空**(与 discard 语义一致:空即无证据,无证据不可继承);env_fp 保持纯相等(旧无-env 报告 None vs 规整后 "" 的不相等会断继承,与现行九轮后行为一致,属有意收紧可接受;若想兼容旧报告可对 env 用"双侧 falsy 视为同源"——但那会重开同类洞,不建议)。同时补守卫:TestEvidenceWriteGuard 增一例 `old fp="" + 金链 skip → 不得继承`,把本探针固化为回归。
   - **优先级理由**:当前报告 56/56 非空不可触发(#4),定 P1 而非 P0;但它是"继承守卫存在但可被空值绕过"的结构缺陷,修复成本 3 行+1 守卫,建议十一轮处理。

### P2

2. **(P2,GPT P1/P2 评估)新增 `last_conformance_passed_at` 字段:建议记档不实施**
   - **schema 影响面**(全部机器核实):
     a. **details 唯一组合**:verified_tools 8 键→9 键 / details 7 键→8 键。三个写入分支(pass L348、继承 L319、conformance elif L420)须**同步**加键,缺一即破九轮刚锁的唯一组合不变量——漂移风险点×3。
     b. **只读校验端** L466-472 的格式断言需决定新字段是否必填(必填则旧报告全红;选填则断言力弱)。
     c. **TTL**(gen_metadata L457-474)只读 `last_passed_at`/`verified_at`,新字段无 TTL 语义位,加了也没人查。
     d. **manifest 投影**:verification_details 全键透传(#14),新字段自动进 ai/tools/*.json。
     e. **surface 哈希**(#13):新字段语义="每次金链 pass 都刷",**必须**加入 `verified_at`/`last_passed_at` 忽略表,否则每次金链通过即 505 surface 假阳性漂移——红队 P1-3 踩过的同一个坑。
     f. **加载端** `_load_verification_report` 不解析时间戳,兼容零成本。
   - **消费方核查**:金链层 n=1(volcano);Agent 面现有 `verification`(level)+ `last_passed_at`(保鲜)已能回答"是否金链+证据新旧";无任何 surface/工具/文档按"金链最近通过时间"查询。
   - **结论**:**记档**。改动面 = 3 写入分支 + 只读断言 + 哈希忽略表 + details 不变量文档,收益 = 一个无消费方的时间戳。若未来金链推广到第二批工具(verification_tiers_note 所述"升级候选")且有 Agent 需要区分"执行保鲜/金链保鲜",再实施并一次性带齐(a)-(e)。
3. **(P2,GPT P2 增量核实成立)`_fp_cache` 函数内作用域:缓存从不跨调用存活,注释与实现漂移**
   - **现状**(探针 #7):`_fp_cache` 定义在函数体内,每次调用重建——0.668s/0.292s 两次全量重 hash。函数 docstring"进程内只 hash 一次(arch F8)"**不成立**。
   - **权衡**:调用频次低(#8,进程内至多 1-2 次),收益约省 0.3-0.7s/进程;但注释声称的语义是假的,属结构诚实性问题,且未来若有热路径调用(如 tool-describe 批量投影 env_fp)会被暗坑。
   - **方案**:提为模块级 `_ENV_FP_CACHE: dict[tuple, str] = {}`(键已是 `(path, mtime_ns, size)`——失效机制内建于键,文件变即新键,无需额外失效逻辑)。**线程安全**:CPython GIL 下 dict get/set 原子,竞态最坏后果=重复 hash 一次,结果一致,无害;无需锁。**测试隔离**:现有 monkeypatch 全部安全——L753 直接替换 `engine_env_fingerprint` 整体(缓存随函数被旁路);identity 测试多 monkeypatch `core.JAR`/PATH 造临时文件,mtime_ns 使键碰撞实际不可能。建议仍加一个 autouse fixture(或 conftest 统一)`_ENV_FP_CACHE.clear()`,防未来有测试在同一路径上原地重写文件并伪造 mtime。**附带动作**:改 docstring,删除"arch F8 进程内只 hash 一次"的旧表述,写明模块级缓存+键内建失效。

### P3

4. **(P3,口径注记)空指纹洞的"缺键"形态被 None vs "" 偶然挡住**:缺键旧证据(`get()`→None)因 `"" == None`→False 不触发继承——正确行为是偶然产物(类型不匹配),不是显式政策。修复 P1-1 时建议把"非空"做成显式判据,消除对 `None != ""` 巧合的依赖。
5. **(P3,观察项,沿九轮)Tier2 fail + 金链 skip + 旧 CONFORMANCE 证据 → 等级继承保留**:九轮 P3-1 记档结论本轮复核仍成立(政策矩阵自洽,不改)。
