## 二、发现（按定额）

### P1-1　workflow.py plan() binding 路径插值跨平台崩溃+静默损坏（GPT 发现独立确认，加重评级）
- **位置**: `tbtools_cli/workflow.py:109-120`
- **机制**: `_bj = json.dumps(binding)` → 字符串 `.replace("{input.k}", str(v))` → `json.loads(_bj)`。占位符位于已带引号的 JSON 字符串内，Windows 值原样注入：
  - `C:\data\sample.fa`：`\d` 非法转义 → **JSONDecodeError 崩溃**（实探针复现）
  - `C:\tmp\new.fa`：`\t`/`\n` 合法转义 → **不崩溃但路径静默损坏**为 `C:<TAB>mp<LF>ew.fa`（实探针复现）——比崩溃更危险，会以错误路径跑分析且 provenance 记录假路径
- **影响面**: 所有走 binding 分支的 workflow step；Windows 是项目明示目标平台（本轮教程即全程 Windows），属发布链硬伤。非 binding 的 args 分支（:134-139）是纯字符串替换，无此问题
- **方案（推荐）**: 放弃 JSON 序列化往返，改为**递归遍历 binding 结构，仅对 str 叶子值做占位符替换**（dict/list/str 三型递归），与 args 分支同机制。约 15 行，无 schema 变更
- **回归测试清单**:
  1. `C:\data\sample.fa`（非法转义崩溃回归）
  2. `C:\tmp\new.fa`（`\t`/`\n` 静默损坏回归——断言替换后字符串含字面反斜杠）
  3. UNC 路径 `\\server\share\x.fa`
  4. 含空格路径 `D:\work dir\`（已有 {workdir} 替换同路径）
  5. POSIX 路径不回归
  6. binding 嵌套（list/dict 内字符串值）替换可达
  7. `{input}` 裸占位 + 无 inputs 报错路径不回归

### P1-2　工具元数据五维覆盖不足（GPT 发现独立确认；同意"核心先行不铺开"）
- **实数**: 1 个五维（iqtree）/ 62 个 ≥3 维 / 235 个 <3 维；PARAMS 仅 7 工具、DEPS 仅 17 工具
- **对 Agent 规划的实际影响（务实判断）**:
  - **CAPS+RELS（187）已覆盖 plan_from_goal 的图搜索主输入**——目标驱动规划在 63% 工具上可用，不是瘫痪
  - **PARAMS=7 是 Agent 填参的真瓶颈**：tool-run 时 Agent 只能猜参数名/类型/默认值，除 7 个 KNOWN_PARAMS 工具外无契约可依，只能退回 tool-describe 的 free-text help
  - **DEPS=17 意味着 preflight 环境检查对绝大多数外部依赖工具（如 blastp 依赖 blast+ 已声明，但还有大量未声明的）无法机器预检**
- **方案（同意 GPT，不铺开）**: 只补**核心 20-25 工具**——选择标准：① 56 个 EXECUTION_VERIFIED 工具（已有执行证据，补契约边际成本最低）② 教程/README 工作流实际引用集（muscle/trimal/iqtree/recipBlast/twoSeqBlast/motif/genestructure/gxffilter/extractFasta/statFasta/heatmap/mcscanx/tree/one-step 等）。两集并集约 25 个，补 PARAMS+SCHEMA+DEPS 三维后，五维完整工具从 1 → ~25，覆盖教程全链路。其余 273 个保持 LEGACY/PARTIAL 诚实标注，不造假
- **反对全量铺开的理由**: 298 工具中 104 个 LEGACY 连 readiness 都不 FULL，为它们写 PARAMS 契约是无验证背书的纸上契约，反而稀释 manifest 可信度
