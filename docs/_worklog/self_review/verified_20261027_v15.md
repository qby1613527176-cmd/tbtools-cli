### 🔴 P1-1(审查一 P1-3 + 审查二 P1,两文共同指控,实证属实): ec=0 但声明产物缺失 → 仍报 succeeded

**代码证据**(executor.py `_execute_step`):
- L189 `step_ok = (_rc == 0) and not _timeout_hit` —— 状态判定只看退出码
- L215/L225 产物验证与登记均要求 `step_ok and out and os.path.isfile(out)` —— 文件不存在时**静默跳过**,`step_ok` 不被翻转为 False
- L260/264 `"status": "succeeded" if step_ok else "failed"`、`"output": out if step_ok and os.path.isfile(out) else None` —— 输出缺失与状态判定脱钩

**探针实证**: `_execute_step({"id":"p1","tool":"--help","args":["/tmp/.../declared_but_never_written.txt"]})` →
`{exit_code: 0, status: "succeeded", output: null, artifact_id: null, output_sha256: null}`——与审查一给出的表格逐字段一致。工作流层(DAG 并行/resume)据此认为步骤成功,下游 `$step.output` 解析到 None,断链被掩盖为成功。

**与「未声明输出」的区分**: 关键在 `out` 是否非空——`out` 非空即本步被识别为应产文件(binding 路径 `_compiled_outputs` 或 legacy 启发式/末参回退命中),此时文件缺失 = 违约;`out==""` 是纯 stdout 工具,合法。当前代码对两者一视同仁。

**定级 P1**。方案:
1. `if step_ok and out and not os.path.isfile(out): step_ok=False`,结构化错误码 `OUTPUT_MISSING`(入 `validation_warning` 或独立字段)
2. 回归测试:「exit 0 + 声明输出 + 无产物」→ status=failed、error=OUTPUT_MISSING;「exit 0 + 无声明输出」→ 仍 succeeded(防误伤 stdout 工具)

**GPT 两方案评估**:
