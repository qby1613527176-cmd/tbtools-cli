## 发现

### P2-1(证实 GPT 审查一-a,独立复核后定级 P2): params_status 实现只有两态,CHANGELOG 宣称四态

**代码实证**(`command_spec.py:1136-1147`):

```python
def params_status(spec) -> str:
    if spec.parameters:
        return "complete"
    return "unknown"
```

函数体内**不存在任何返回 `"partial"` 或 `"confirmed_none"` 的代码路径**——两个状态不可达。函数 docstring 本身是诚实的(注明 partial=「预留」、confirmed_none=「待逐工具确认后收编」),但 `CHANGELOG.md:11` 写:

> **P1 params_status 四态**: metadata 注入 complete/partial/confirmed_none/unknown

探针独立复算(不复述 GPT):全量 298 条目 metadata 实际分布 `complete=8 / unknown=290`,partial 与 confirmed_none 各 0 次。「四态注入」与实现/产物不符,属文案过度宣称。

**定级 P2 而非 P1**: 十四轮 P1-1 的核心语义——「空 parameters 不得默认为无参数(unknown≠none)」已正确交付,8/290 两态划分本身无误;缺陷仅在 CHANGELOG 把预留状态写成已注入。**方案**:CHANGELOG 措辞改为「两态注入(complete/unknown),partial/confirmed_none 预留待逐工具审计」;或代码注释与 CHANGELOG 对齐注明状态机为渐进式。confirmed_none 收编需逐工具审计(维持十四轮原判断)。

### P1-1(证实 GPT 审查一-b): params_status 未投影到 Agent 静态面(ai/tools/*.json + tool-index.jsonl)

**代码实证**(`scripts/gen_metadata.py:655-664`):ai/tools 逐工具 schema 的 trust 字段补齐循环白名单为:

```python
for _k in ("semantic_fingerprint", "semantic_fingerprint_short", "readiness", "verification",
           "relations", "output_slots", "parameters", "dependencies", "dependency_manifest",
           "aliases"):
```

**不含 `params_status`**;初始 schema dict(L644-650)亦无。tool-index.jsonl 条目构造(L628-638)同样不含。

**探针实证**: `ai/tools/expr/volcano.json` keys = [capabilities, class, description, group, id, inputs, invoke, kind, name, output_slots, outputs, parameters, readiness, relations, schema_version, semantic_fingerprint, semantic_fingerprint_short, status, verification, verification_details] —— **params_status 缺失**(尽管 command_metadata.json 中 volcano 为 `complete`);`ai/tool-index.jsonl` 条目 keys 亦缺失。

**定级 P1**: 十四轮 P1-1 的动机原文是「**Agent 可区分**参数契约完整 vs 未审计」。运行时 `tool-describe` 路径可读到(command_metadata.json 消费端),但 Agent 的**静态发现面**(ai/tools 逐工具 manifest + 搜索索引 tool-index.jsonl——评审 #112 P1 专门防「tool-describe 信息完整 / ai/*.json 被削薄」双世界分裂的那条投影链)恰好漏掉了新字段,同构双世界分裂复发。修复为白名单加一项 + index entry 加一项,<5 行。**方案(与 GPT 一致,独立得出)**:投影已实现的两态(complete/unknown)到 manifest,不宣传未实现状态;confirmed_none 待逐工具审计后再收编。

### P3-1(证实 GPT 审查二机制属实,维持记档): env_fingerprint 全局粒度粗,拆分层前置条件未满足

**代码实证**(`identity.py:165-244`): `engine_env_fingerprint()` 对 JAR + plugins/lib 全部 jar(sorted listdir)+ **全部**外部二进制(从 KNOWN_DEPENDENCIES_STRUCT 动态派生 executable 去重集)做单一 sha256 链。`command_spec.py:1262-1278` 加载端:任一输入变化 → env_fp 不匹配 → `_exec.discard` 全部工具。即任一外部二进制(如与本工具无关的 hmmsearch)升级 → 56 个 verified 工具全部降级,GPT 描述的误伤机制成立。

**独立评估局部化可行性**(本轮新证据,超出 GPT 原判):KNOWN_DEPENDENCIES_STRUCT 已含 17 工具的 executable 映射,且 56 verified 中 6 个(iqtree/kallisto/mcscanxd/muscle/plotrna/trimal)有声明——**依赖映射并非空白**,十四轮「可信依赖映射未建」的判断需修正为「映射存在但稀疏(6/56 verified 覆盖)」。然而:① 50/56 verified 工具无映射,局部化只能做混合方案(有映射的按工具算、无映射的退回全局保守),收益有限;② 所有工具共享 JAR + 插件 jar,这部分指纹任何局部化方案都必须全局——JAR 升级本就应全库降级,局部化只能救「外部二进制升级」一类场景;③ 映射的正确性未审计(如依赖 plugin 内部二进制的工具若漏声明,局部 fp 会漏判环境变化=反向误伤,比粗粒度更危险)。低成本方案(仅对 6 个有映射工具拆分)安全但不解渴;全量拆分需先补全并审计映射,成本未降。

**定级 P3 记档确认**(维持十三/十四轮结论,修正其前提描述):机制缺陷属实,拆分方案的前置条件是「verified 工具依赖映射补全+审计」,此前提未满足前全局保守语义(换任何依赖全库降级)是正确默认。建议下次补全 KNOWN_DEPENDENCIES_STRUCT 时重新评估。
