## 二、发现

### P1-1(第八轮唯一 P1):旧 CONFORMANCE_VERIFIED 继承路径不可达(GPT 发现属实)

**代码事实**(tests/test_conformance_verified.py `_build_report_and_persist`):

1. `_verified_tools` 构建循环:每条目 `"level": "EXECUTION_VERIFIED"` 硬编码;
2. 随后 conformance 升级循环:`_old_conf = (_t in _verified_tools and _verified_tools[_t].get("level") == "CONFORMANCE_VERIFIED")`——此时 `_verified_tools` 里**不可能**有任何 CONFORMANCE_VERIFIED 条目,`_old_conf` 恒 False;
3. 注释声明的语义("旧报告已是金链 → 继承保留")实际应从 `_old_verified`(盘上旧报告)读,但代码读错了对象。

**探针实证**(隔离 tmp_path,monkeypatch 指纹固定,4 场景):

| 场景 | 旧证据 level | 本次金链 | 期望 | 实际 |
|:--|:--|:--|:--|:--|
| A | CONFORMANCE_VERIFIED | skip | CONFORMANCE_VERIFIED(继承) | ❌ EXECUTION_VERIFIED,名单空 |
| B | CONFORMANCE_VERIFIED | 未运行(None) | CONFORMANCE_VERIFIED(继承) | ❌ EXECUTION_VERIFIED,名单空 |
| C | CONFORMANCE_VERIFIED | fail | EXECUTION_VERIFIED(降级) | ✅ EXECUTION_VERIFIED |
| D | 任意 | pass | CONFORMANCE_VERIFIED(升级) | ✅ CONFORMANCE_VERIFIED |

**后果**:金链测试在无 JAR 环境 skip(tests/test_conformance.py:51),此类环境写报告 → volcano 金链级静默降级;只读校验下次运行比对 `_want_conf`(∅)vs 盘上({volcano})→ 漂移误红,或 WRITE 模式下证据链被静默削弱。与七轮 P1-A(semantic_checked 回溯升级)互为镜像:一个是"该降不降",这个是"该继承不继承"——同一继承语义需要旧等级读旧报告。

**修复建议**(不改代码,供决策):

```python
# 从 _old_verified 读旧等级,而非刚重建的 _verified_tools
_old_entry = _old_verified.get(_t, {})
_old_conf = _old_entry.get("level") == "CONFORMANCE_VERIFIED"
# fail = 明确反观测 → 必须降级; skip/None = 无观测 → 允许继承
# 追加同源守卫: contract/env 指纹须与旧证据一致才可继承(防旧金链结论
# 贴到新契约证据上——继承的是"该契约+环境的金链观测",契约变了结论失效)
_fp_same = (_exec_entries.get(_t, {}).get("contract_fingerprint")
            == _old_entry.get("contract_fingerprint")
            and _exec_entries.get(_t, {}).get("env_fingerprint")
                == _old_entry.get("env_fingerprint"))
_allow_conf = (_gold == "pass") or (_old_conf and _gold != "fail" and _fp_same)
```

**回归守卫建议**(2+1 个):

1. `test_conformance_inherit_on_golden_skip`:旧 CONFORMANCE_VERIFIED(fp/env 一致)+ Tier2 pass + 金链 skip → 最终 level 仍 CONFORMANCE_VERIFIED 且在 conformance_verified 名单;
2. `test_conformance_downgrade_on_golden_fail`:同上但金链 fail → 降级 EXECUTION_VERIFIED、出名单(与场景C 对应,锁死 fail 语义);
3. (建议追加)`test_conformance_no_inherit_on_fp_change`:旧 CONFORMANCE_VERIFIED + 金链 skip + contract_fp 已变 → 不继承(金链观测绑定旧契约,不得跨契约继承)。
