## 四、GPT 审查二 P1/P2：validate_artifact 校验强度的文档一致性 🟡（基本一致，1 处版本小漂移 + 强度未量化）

### 机器核验实现（executor.py L559-616）
- FASTA：head 8KB 内 `>` 开头且计数≥1
- GFF：`##gff-version` 或 tab 分隔 gene/mRNA/CDS 关键词
- Newick：有括号且分号结尾
- TSV/CSV/TXT：≥1 非空行
- SVG：含 `<svg` 或 `<?xml`
- 压缩：剥 .gz/.bgz/.bz2 取逻辑格式 + 解压读头
- 无解析器：返回 `(True, "unchecked(ext, no parser)")`——**通过但标注未校验**

### 与文档比对
- §6.2 边界表 L169 已正确声明「`unchecked(...)` = 无解析器未校验，非已验证通过」✅（十九轮 unchecked 语义改动已同步）
- **GPT「现状仍是启发式」属实**：实现是 8KB 头部启发式，非逐记录解析。§6.2 只写「产物校验结论(validate_artifact 结果, 含层级标注)」，**未量化强度**——Agent 无法从文档区分「fasta seqs=3」是解析级还是启发式结论。建议（P2）：§6.2 该行「能证明」列补「头部启发式(前 8KB)校验通过」，「不能证明」列补「文件完整性/全量记录合法（大文件尾部损坏不可检出）」。
- **小漂移（P3）**：§6.2 写「v1.5.8 起持久化到索引」——机器核验：字段 v1.5.8 引入（CHANGELOG v1.5.8），但**索引持久化**是 v1.5.9 P2（e8b4f67「metadata.validation 持久化」），resolve_artifact 恢复更是 v1.5.10 P2。建议改为「v1.5.8 引入，v1.5.9 起持久化到索引」。
