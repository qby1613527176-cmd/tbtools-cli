## 一、MCP JSON 错误响应违反自身协议 —— ✅ GPT 属实，定级 **P1**

### 协议要求（docs/agent-protocol.md L14）
> **schema_version 必带**: 所有 JSON 输出含 `"schema_version": "1.0"`

且 L31-32 规定统一响应结构含 `status: success | failed | not_ready`。

### 实证（嵌入模式实跑，`TBTOOLS_MCP_EMBEDDED=1`）

**分支 1：`search("")` 空查询**（mcp_server.py L99-108）
```json
{"query": "", "hits": [], "error": "query 为空", "usage": {...}}
```
❌ 无 `schema_version`，无 `status`。`error` 还是裸字符串而非 `{code, message, retryable}` 结构——与 `_cli()` 错误 envelope 的结构（`error.code`）也不一致。

**分支 2：`tool_run()` 参数类型校验失败**（L186-190）
```json
{"error": {"code": "INVALID_PARAMETER_TYPE", "parameter": "pval_cutoff", "expected": "float", "received": "abc", "retryable": false}}
```
❌ 无 `schema_version`，无 `status: "failed"`。error 子结构本身合规，但外层缺两字段。实测确认（pval_cutoff 传 `"abc"`）。

**对照分支（合规）**：
- `_cli()` 的 TIMEOUT / CLI_ERROR / embedded 非 0 三条路径均带 `schema_version` + `status: "failed"` ✅
- `search("volcano")` 正常路径透传 CLI JSON，带 `schema_version: "1.0"` ✅
- `workflow_plan()` 返回带 `schema_version: "1.1"` ✅（注意：与协议文档的 "1.0" 存在版本口径分叉，但属 workflow 子协议，已正式化于评审 #82，不计缺陷）

### 全方法返回分支枚举

| 方法 | 正常 | 错误分支 | 合规性 |
|:--|:--|:--|:--|
| search | 透传 CLI（✅） | 空查询本地构造（❌ 缺 schema_version/status）；CLI 输出不可解析时原样返回裸文本（⚠️ 透传非 JSON，边缘） | **不合规** |
| tool_describe | `_cli` 透传 | 全部走 `_cli` envelope | ✅ |
| tool_validate | `_cli` 透传 | 全部走 `_cli` envelope | ✅ |
| tool_run | `_cli` 透传 | INVALID_PARAMETER_TYPE 本地构造（❌ 缺 schema_version/status） | **不合规** |
| workflow_plan | 本地构造（✅ schema_version 1.1） | plan_from_goal 异常未捕获（⚠️ 抛异常给 MCP 框架，非结构化） | 基本合规 |
| job_submit/status/result、tool_provenance | `_cli` 透传 | 全部走 `_cli` envelope | ✅ |

### 结论与方案
**P1 成立**。MCP 是 Agent 的第一入口，两条高频错误路径（首次空调用、参数类型错误）恰是 Agent 最可能先撞到的路径——它们恰好不合规，Agent 按协议解析 `schema_version`/`status` 会拿到 None。

**最小方案**：
1. mcp_server.py 顶部加 `_envelope(payload, status="success")` / `_err_envelope(code, message, **kw)` 统一构造函数（含 schema_version/status/error 结构），`_cli()` 与本地构造分支共用；
2. `search` 空查询分支改走 `_err_envelope("EMPTY_QUERY", ...)`，usage 提示保留为 `error.hint`；
3. 契约测试：对每个 MCP 方法的全部可触发分支断言 `schema_version` + `status` 存在（参数化测试，~10 例）。

## 二、FULL 分级不依赖 params_status —— ✅ GPT 属实，定级 **P1**

### 源码事实（command_spec.py L1149-1168）
`agent_readiness()` 注释自证：
```python
params_declared = True  # 恒真(见上)——FULL 判定实际只靠 caps/schema/outputs/status
```
FULL = caps + inputs + outputs + status==stable，**参数维度完全不参与**。

### 实证统计（机器核验，非估算）
```
total 298  FULL 60  FULL 且 params_status=unknown: 52
```
**60 个 FULL 工具中 52 个（87%）参数契约状态为 unknown**——包括 volcano 的近邻 pca/venn2-4/upset/circos/muscle/trimal/kallisto/mcscanxd 等主力工具。仅 8 个 FULL 有 KNOWN_PARAMS 契约。

### 语义缺口
Agent 看到 `readiness: FULL` 的合理推断是"契约完备可按 schema 调用"，但对 52/60 的 FULL 工具，`params_status=unknown` 意味着"参数面根本没审计过"。"工具具有参数字段"≠"参数已审计"——GPT 定性准确。十四轮已把 params_status 注入 metadata（缓解：Agent 可自查），但**分级标签本身仍夸大承诺**。

### 定级与方案
定 **P1**（标签语义误导 Agent 决策，影响面 87% 的 FULL 工具）。注意十六轮只修了两态勘误（unknown 不再宣称"无参数"），未碰分级——本项是遗留的下一刀。

**最小方案（二选一）**：
- **A（保守，推荐）**：manifest/metadata 中 FULL 标签旁显式投影 `params_status`，并在 readiness 文档注明"FULL 不含参数维度"；同时把 `params_status=unknown` 的 FULL 在 census 中拆出子计数（如 `FULL(params_verified: 8, params_unknown: 52)`）——零降级、零破坏，仅消除歧义。
- **B（彻底）**：FULL 判定加 `params_status != "unknown"` 条件 → 52 个工具降 PARTIAL。语义最诚实，但发布面冲击大（README/census 数字 60→8），需用户决策。

建议本轮先做 A，B 待参数审计覆盖扩大后收编。

## 三、bash fallback 不处理 verbose/quiet —— ✅ GPT 属实，定级 **P2**

### 源码事实（cli_load.py L327-396）
`_cmd_impl(ctx, verbose, quiet, fmt, preset, height, width, threads)` 签名接收两 flag，L400-401 注册 `--verbose/-V`、`--quiet/-q` 为 Click 选项：
- **impl 分支**（L380-381）：`impl(args, verbose=verbose, quiet=quiet)` ✅ 透传
- **fallback 分支**（L385-391）：`bash_args = [bash, tbplot.sh, name] + args`——❌ verbose/quiet 既不追加也不映射

### tbplot.sh 侧核实（bin/tbplot.sh L13-23, L103-107）
tbplot.sh **原生支持** `--verbose|-V` 与 `--quiet|-q`：脚本头部解析、从参数列表剥离不传给引擎（L107）、控制堆栈显示/进度输出。即语义完全可映射，不是"不适用"。

### 后果
所有无手写 impl 的动态绘图命令（fallback 主力：volcano/heatmap2/pca 等十六轮刚修过 fmt/preset 丢失的同一批路径），用户传 `--verbose` 调试 Java 堆栈或 `--quiet` 压日志时，**flag 被 Click 消费后静默消失**——与十六轮修的 threads 丢失同构（L366 注释还留着那段教训），属于同一类"Click 消费-底层丢失"缺陷的残留面。

### 方案（最小）
fallback 构造 bash_args 时追加：
```python
if verbose: bash_args.append("--verbose")
if quiet:   bash_args.append("--quiet")
```
tbplot.sh L107 已保证剥离不污染引擎参数。加一例回归测试（mock subprocess.run 断言 flag 在 argv 中）。
