### P2-1（GPT P2 时区不对称）— **属实，独立复现**

**核实**：`gen_metadata.py:436` `_now2 = _dt2.datetime.now()`（本地墙上 naive）；`_parse_naive()` 把 aware ts 转 UTC 再剥 tz。**两侧基准不同**：当前时间=本地 naive，历史=UTC naive。

**探针实证**（UTC+8 机器）：

```
真实年龄 89.83 天的 aware(+08:00) ts → 判龄 90 天（虚增 +8h，越过 90 天红线 → strict 误红）
同龄 naive 本地 ts → 判龄 89 天（正确）
```

**GPT 低估的一点**：不对称**不限于 aware ts**。写入端（test_conformance_verified.py:343）写的是 naive **本地**时间——nightly 跑在 GitHub UTC runner 上刷新 last_passed_at 后，UTC+8 开发机本地 --check 同样虚增 +8h。即「跨时区写读」即使全 naive 也触发。当前 56 条是 +8 机器写的本地 naive，恰好与 +8 读端自洽，所以**现网零暴露**；但 nightly 下次保鲜回写（UTC naive）后立即产生暴露面。

**影响评估**：仅 90 天边界 ±|tz offset| 窗口内的条目受影响（最多 ±14h）；strict 模式误红 / soft 模式伪告警各一种。判龄粒度是天，非边界无影响。

**修复建议**（成本 ~10 行）：

1. 写入端：`datetime.now(datetime.timezone.utc).isoformat(timespec="seconds")`（aware UTC）
2. 读取端：`_now2 = datetime.now(datetime.timezone.utc)`，`_parse_naive` 返回 aware（naive 输入按**文档化规则**解释为 UTC 并告警一次，或按本地解释——二选一写进 docstring）
3. 比较统一 aware-aware
4. 过渡期：旧 naive 报告的 ±8h 偏差可接受（TTL 是 90 天粒度），无需回填
