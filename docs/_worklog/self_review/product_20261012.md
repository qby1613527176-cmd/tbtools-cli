## 发现

### P1×1

**P1 — 单工具 Agent manifest(ai/tools/*.json)的 verification_details 投影缺 last_passed_at, 与文档承诺直接矛盾。外部 GPT 发现属实。**

- 代码位置: `scripts/gen_metadata.py:621-630`(render_ai_manifest 投影白名单), 字段集 = level / contract_fingerprint / env_fingerprint / verified_at / corpus / semantic_checked / domain_note——**无 last_passed_at**。
- 证据:
  - 权威报告 `tbtools_cli/verification_report.json` muscle 条目: `verified_at=2026-10-06T03:59:46`, `last_passed_at=2026-10-12T14:54:29`;
  - 生成物 `ai/tools/seq/muscle.json` 的 verification_details **只有 verified_at(10-06)**, Agent 读静态 manifest 看不到 10-12 的再次通过, 无法判断证据新鲜度。
  - 矛盾放大点: `docs/agent-protocol.md:97` 明确写 verification_details 存在于「tool-describe --json **/ ai/tools/*.json**」且示例含 last_passed_at, §6.1(121 行)又指示「Agent 判定验证是否新鲜应读 last_passed_at」——文档对两个面做了同一承诺, 但只有一个面(describe)兑现。读静态 manifest 的 Agent 被文档误导。
- 影响面: 双世界分裂——describe 通道(在线)有保鲜时间, manifest 通道(静态/离线/PyPI 包内 ai/)没有。56 个 ai/tools 文件全部受影响。
- 修复建议(按依赖序):
  1. **投影补字段**(一行): gen_metadata.py:621-630 白名单加 `"last_passed_at": _verif_details.get("last_passed_at", _verif_details.get("verified_at", ""))`(回退 verified_at 兼容旧报告, 与 cli_top.py:730 同语义)。
  2. **surface gate 规范化已就位, 无需改动**: gen_metadata.py:341-345 `_strip` 已同忽略 verified_at/last_passed_at, 补字段后 `--check` 不会因时间戳刷新产生假阳性(本轮已读码确认)。
  3. **生成流程配套**: `.github/workflows/nightly-e2e.yml` Report writeback 步 `add-paths` 目前只有 `tests/verification_report.json`——report 刷新后 ai/tools manifests 不会夜间重生成, 投影字段仍会滞留在上次人工 render 时的值。建议 writeback 步在 report 刷新后跑 `python3 scripts/gen_metadata.py --render` 并将 `ai/` 加入 add-paths。
  4. **防无意义全仓漂移**: 若 (3) 直接提交重渲染产物, 每晚 56 个 ai/tools 文件仅时间戳变化也会产生 churn。建议 writeback 提交前用与 `--check` 相同的规范化哈希(`_strip` 后)比较: 仅当规范化内容变化、或文件缺失时才把该 manifest 纳入提交; 纯 last_passed_at 刷新的 manifest 是否提交可策略选择(要保鲜语义就提交, 要仓库安静就不提交、靠 describe 通道供鲜)——**推荐提交**, 因为 §6.1 承诺的正是静态面可读新鲜度, 否则 P1 只修了一半。每晚 ≤56 个 JSON 单行时间戳 diff, 由 automation label PR 承载, 可接受。
