## 逐项发现（新增 + 未闭环）

### N1. TTL 严格门禁缩进回归：strict 模式无条件 fail，nightly 证据保鲜链已断 —— P0（新增，回归）

**位置**：scripts/gen_metadata.py L437-453（main 内 --check 分支）；引入提交 a993d03（v1.4.88，"gen_metadata 9 处 except pass 告警可见化"）。

**发现**：v1.4.70（933787d）原始结构为 `for ...: 收集 _old_days` 后 `if _old_days:` 守卫 + 判定块在循环**外**。a993d03 在给单条 `except: pass` 加注释时删掉 `- if _old_days:` 行，判定块（_msg 构造 / `if _ttl_strict: return 1` / 软告警 print）整体左缩进错误、被吞进 for 循环体（AST 证实：loop body = [Assign, If, Assign, If, Expr]）。后果实测：

- **strict（TBTOOLS_TTL_STRICT=1）**：`if _ttl_strict: print; return 1` 无任何"存在超龄"前置条件，56 条 verified_tools 非空 → 第一条迭代即 return 1。本机实跑：`TBTOOLS_TTL_STRICT=1 gen_metadata --check` 输出 `❌ 验证超龄 0 个(>90 天, TTL 严格模式阻断):`（**0 个超龄仍失败**），REAL_EXIT=1。
- **soft（默认）**：软告警 print 在循环体内且无 `_old_days` 非空条件 → 每次 --check 打印 **56 条**"验证超龄(0 个...)"伪告警（实测 `grep -c` = 56），真告警将被噪音淹没。
- **nightly 连带**：nightly-e2e.yml 步骤序为 refresh(WRITE_REPORT=1) → **TTL gate(strict)** → create-pull-request（默认 `if: success()`）。TTL 恒红 → **保鲜 PR 步骤永远被跳过**。报告 verified_at 停留在 10-06/07（本机手工跑出来的），恰好印证自动保鲜链自 v1.4.88 起未产出过 PR。当前证据尚未超 90 天 TTL，但一旦超龄，机制既不能正确报警（恒红=无信号）也不能自动修复（PR 链死）。

**建议**：恢复 `if _old_days:` 守卫并把判定块移出 for 循环（回到 933787d 结构，保留单条 except 注释）。补一个直接单测：构造空 `_old_days` + strict → 断言 exit 0；构造 1 条超龄 + strict → 断言 exit 1（v1.4.90 的 source_scan 合成源码单测模式可复用）。

**严重度**：P0（门禁完整性破坏 + 证据保鲜自动化死亡；且是回归——上一轮审查时该机制"在位且正确"，本轮已坏）

### N2. bin0 xfail 活测试名存实亡：引擎转为部分命中后判据失效，测试恒 PASS 无信号 —— P1（新增）

**位置**：tests/test_conformance_verified.py L454-482（test_bin0_defect_xfail）；证据关联 verified_tools.peakanno/peaktss.domain_note。

**发现**：本机真实 JAR 全量实跑：62 中 60 passed + 2 xfailed——两个 xfail 是 pafref/tfbsShift（缺陷仍在，活监控有效✅），而 **bin0 两条（peakanno/peaktss 低坐标）是 PASSED 而非 xfail**。手工复现 peakanno 低坐标用例：exit 0，产出 38B tsv——**3 个低坐标 peak 只注释到 1 个**（9200-9500→gene3；1100-1400、5100-5400 两个 peak 漏注释）。即引擎行为从"静默空跑（无产物）"变为"部分命中（有产物但漏 2/3）"，缺陷**实质仍在**，但测试判据 `real = [a for a in arts if size>0]`（产物非空即过）对"部分命中"无鉴别力 → `if not real: pytest.xfail()` 永不触发 → 恒 PASS。三层失真：

1. **叙事与实测不符**：domain_note"bin0 engine defect documented (v1.4.57 xfail)"、LEFTOVER/测试注释"缺陷已固定(xfail 测试)"——实测 xfail 分支是死代码，什么都没固定住。
2. **修复方向也无信号**：条件 xfail（非 `@pytest.mark.xfail(strict=True)`）下，即便 JAR 彻底修复，测试只是静默 PASS——注释承诺的"xpass 翻红提示复测"不存在（xpass 翻红是 strict 标记 xfail 的特性，条件 xfail 没有）。TestKnownDefectsXfail（pafref/tfbsShift）同构缺陷：部分修复（如 exit 0 + 空产物以外的任意非空输出）也会静默 PASS。
3. **证据链语义皱褶**：domain_note 作为 evidence 字段声称"验证仅覆盖 coords>=10000 域"目前仍然为真（缺陷未修），但若引擎再变（完全修复或彻底坏掉），没有任何机制触发该 note 的复核。

**建议**：① bin0 判据从"产物非空"升级为内容级——期望 3/3 peak 全注释（genes_low/peaks_low 是合成数据，期望结果确定，可直接断 gene1+/gene2-/gene3+ 全出现，复用 `_peakanno_map_ok` 模式）；不满足则 xfail（缺陷未修/部分修复），满足则 PASS（真修复，提示摘除）。② pafref/tfbsShift 同样把判据收紧到"缺陷特征消失"（如 pafref 产物含覆盖度数值行），而非 exit0+非空。③ 或整体改 `@pytest.mark.xfail(strict=True, reason=...)` + 内部 assert——strict xpass 会变红，双向都有信号。

**严重度**：P1（活监控机制失效 + 证据字段叙事失真；标签本身暂未说谎，故不到 P0）
