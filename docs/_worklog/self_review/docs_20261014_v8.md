## 二、GPT 整体评价独立核实

### 🟡 GPT P1: CommandSpec 唯一契约入口 + 旧式来源退役边界——**结论: 部分成立,发现 1 个 GPT 未点名的实证(P2)**

**当前统一程度(独立核实,非照抄)**:
- 运行时分组解析已是 CommandSpec 优先:`cli_load._group_of()` = `_SPEC_GROUPS`(CommandSpec 投影)→ `CATEGORY_MAP` 兜底;CATEGORY_MAP 本体标 `⚠️ DEPRECATED(Phase 2)` 注释。
- 纪律有机器守卫:`test_registry_discipline.py` 禁止新模块直接 import 三个 legacy 注册源(实跑通过)。
- CommandSpec 自证方向性正确:manual 命令分组从**装饰器前缀**推断(不再用 CATEGORY_MAP 回退错标 engine);metadata fallback 已退(red 队 P1-1),真源=源码 AST 扫描。
- **实跑交叉比对**(specs 298 vs CATEGORY_MAP 189 vs tbplot.sh 140):
  - tbplot.sh 140 命令全部在 specs 内(无 tbplot-only 幽灵)✅
  - spec-not-in-cat 为 CLI_TOOLS(tool 组)+ 大写注册别名,属设计内 ✅
  - **cat-only 幽灵 = `gxfSort`**:只存在于 CATEGORY_MAP,在 auto_commands/cli.py/tbplot.sh/command_metadata/command_spec 全部查无此命令(6 源 grep 零命中)。纯死条目,运行时无害(永不注册),但正是 GPT 所说"只出现在某入口"的幽灵——**且现存所有守卫(discipline 守卫管 import 方向、--check 管生成面、doc_consistency 管数字)都不查跨源成员一致性**,无任何机制能发现它。

**退役边界清晰度**:
- CATEGORY_MAP:边界清晰(DEPRECATED 注释 + _group_of 单一读取口 + import 纪律守卫)。
- tbplot.sh 分发:双重角色——①命令分发源(_load_dynamic_commands 读取)②运行时 bash 兜底(无 impl 时)。兜底是有意保留的逃生舱(Windows Git Bash 提示清晰),README 退役计划只针对"旧入口"语义,两者未在文档中明确区分,轻微含糊但不矛盾。
- **缺失**:GPT 建议的"入口一致性检查"不存在——没有任何测试断言 specs ⊇ CATEGORY_MAP、tbplot.sh ⊆ specs 这类集合关系。本次人工比对才发现 gxfSort,证明缺口真实。

**判定: P2**(统一程度已高、纪律守卫在位,缺的是跨源成员一致性守卫这一小块;gxfSort 死条目顺手清)。
**方案**: ①新增 `test_entrypoint_consistency.py`:断言 `set(CATEGORY_MAP) ⊆ set(build_command_specs())`(或显式记档例外)、`tbplot.sh 命令集 ⊆ specs`;②新增工具只走 CommandSpec(在 CONTRIBUTING/RELEASING 加一句明文化);③删除或补注册 gxfSort(查 TBtools 是否有 GxFSort 引擎再定)。
