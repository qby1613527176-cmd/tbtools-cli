## GPT P1 结构面核实(conformance 继承不可达)——属实, 与 verified 探针一致

GPT 声称: conformance 升级循环 `_old_conf = (_t in _verified_tools and _verified_tools[_t].get("level") == "CONFORMANCE_VERIFIED")` 检查的是**刚重建**的 `_verified_tools`(前循环每条目 level 硬编码 EXECUTION_VERIFIED), 历史等级从未从 `_old_verified` 读 → 继承支路恒 False(死代码)。

**结构面核实**(代码精读):
- `_build_report_and_persist()` 流程: ① Tier1/Tier2 构建 `_exec_entries` → ② 遍历 `_exec_entries` 构建 `_verified_tools`(level 硬编码 "EXECUTION_VERIFIED") → ③ conformance 循环检查 `_verified_tools[t].level`。
- ② 与 ③ 之间无任何"从旧报告读等级"的环节——继承逻辑(arch 七轮已建 `_CONFORMANCE_RESULTS` 容器)只解决了"金链观测来源", 未解决"旧金链等级保留"。
- 与 verified 探针 4 场景一致: skip/未运行 → 错误降级 EXECUTION_VERIFIED; fail → 正确降级; pass → 正确升级。

**修复落点**: 八轮已验证修复——`_old_conf` 改从 `_old_verified.get(_t, {}).get("level")` 读, 追加 contract/env fp 同源守卫(`_fp_same`), 政策: `_allow_conf = (_gold == "pass") or (_old_conf and _gold != "fail" and _fp_same)`。

## GPT P2 结构面核实(conformance 测试隔离)——属实, 随 helper 参数修复

GPT 声称: helper `_build_with_results()` 隔离 `_TIER2_RESULTS` 但未隔离 `_CONFORMANCE_RESULTS` → 前序金链测试残留 pass 污染(顺序依赖)。

**结构面核实**: 五轮 helper 仅 patch `_TIER2_RESULTS`/`CONFORMANCE_VERIFIED`/`SEMANTIC_CHECKS`; 七轮加 `_CONFORMANCE_RESULTS` 容器后 helper 未同步注入——旧守卫 `test_conformance_upgrade_with_golden_chain_pass` 手动 patch `_CONFORMANCE_RESULTS` 到进程级容器, 若他测先跑会读到残留。

**修复落点**: helper 增 `conformance_results` 参数(缺省注空 dict 隔离), 所有 conformance 测试显式传参。
