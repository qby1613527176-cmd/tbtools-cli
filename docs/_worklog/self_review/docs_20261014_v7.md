### 🟡 F2: env_fp 是否含插件文件名 —— **文档确实未定义, P2 确认成立**

独立核实 identity.py `env_fingerprint()`(L175-243):

- 插件 JAR 经 `sorted(os.listdir(plugins/lib))` 枚举(十一轮已固定顺序), 但指纹仅由 `h.update(_hash_file(_p).encode())` 构成——**喂入哈希的只有文件内容的 SHA-256 hex, 文件名/路径完全不进入哈希输入**。
- 即: **重命名一个插件 JAR(内容不变) → env_fp 不变**; env_fp 是「内容身份」而非「名称+内容身份」。
- 副作用评估: 改名但内容不变的 JAR 若被引擎按名加载而行为不同(极端), 证据会误迁移——但实际 TBtools 插件按内容加载, 语义保守方向正确(内容同则证据可继承); 反向(同名不同内容)已被内容哈希覆盖, 无漏洞。

§6.1 当前对 env_fp 的表述只有「JAR + plugins/lib 全部 jar + KNOWN_DEPENDENCIES 派生的全部外部二进制哈希」与「全局单值/爆破半径」, **未明示「身份=内容哈希序列, 与文件名无关」**。GPT 此点成立。

- **方案**: §6.1 env_fp 段补一句定义, 如:
  > **env_fp 是内容身份**: 由各文件内容的 SHA-256(按固定排序拼接)派生, **不含文件名/路径**——插件 JAR 改名但内容不变时指纹不变, 证据可继承; 同名替换内容则指纹必变。
- 定额: **P2**(语义澄清, 防下游误读「同构环境」口径)。
