## 二、发现（按严重度）

### 🔴 P1-1：`--threads` 在封装层被静默吞掉（GPT P1 独立实证——属实，且比 GPT 描述更宽）

**实证链（三重独立证据）：**

1. **动态命令（cli_load.py `_make_passthrough`）**：L358 注册 `("--threads","-t")` click option → `_cmd_impl(ctx, ..., threads)`（L295）签名接收 `threads` 但**函数体从未使用该变量**；`impl(args, ...)` 只传 `ctx.args`。用 CliRunner + 假 impl 实测：
   - `cmd in.fa out.aln --threads 8` → impl 收到 `['in.fa','out.aln']`
   - `cmd in.fa out.aln -t 4` → impl 收到 `['in.fa','out.aln']`
   - click 把 `--threads` 作为已声明 option 消费，不落入 `ctx.args`（`ignore_unknown_options` 只保未知 token）。
2. **受害面 = 真正需要 threads 的引擎**：auto_commands 中 muscle（L561 自解析 `--threads`→`-threads`）、kallisto（L449/478 `-t`）、findhomolog、iqtree、bestid（L593 注释自述"CLI 公共 -t 会吃掉它"——项目已知该坑但只对 bestid 用注入缺省值绕开，其余未修）等。Agent 按 help 传 `--threads 8` → 调用成功、exit 0、引擎以默认线程跑——**静默失效**。
3. **手写命令（cli.py `common_options`，L60-62）**：`--threads/-t/--runtime-threads` 三 alias 绑同一 kwarg `threads`（Click 语义上合法，无冲突），但火山/热图/pca 等全部手写命令体同样**从不消费 `threads`**（grep 确认 cli.py 中 `threads` 仅出现于声明与签名）。绘图命令不需要线程尚可辩白，但 Agent 契约面把无效参数暴露在 help 里。

**tool-run 路径同样中招**：tool_run（cli_top.py L1073）走 `cli.main(list(args))` 重分发 → 同样经过 click 解析 → 同样吞。Agent 主入口无豁免。

**附带发现（语义分裂）**：动态命令只声明 `--threads/-t`，`--runtime-threads` 因 `ignore_unknown_options` 被**原样漏进引擎 args**——同一参数名在两类命令下行为相反（手写命令：双 alias 都吞；动态命令：`--threads` 吞、`--runtime-threads` 漏给引擎）。L60 注释声称"评审 #12 命名空间修复"实际未闭环。

**方案：**
1. 动态命令 `_cmd_impl`：若 `threads is not None` 且 `ctx.args` 中无 `--threads`，回填 `args += ["--threads", str(threads)]`（让引擎自解析，与 muscle/kallisto 现有解析兼容）；
2. 动态命令 option 声明补齐 `"--runtime-threads"` alias，与 `common_options` 对齐，消除漏 token；
3. 手写绘图命令：要么从 `common_options` 摘出 threads（不需要的命令不暴露），要么文档化"仅部分命令生效"——优先前者，契约诚实；
4. **回归测试**：假 impl 断言 `--threads 8` 后 args 含 `["--threads","8"]`；tool-run 端到端断言同。把 bestid 的已知坑注释升级为测试固化。

### 🟡 P2-1：MCP 嵌入模式（TBTOOLS_MCP_EMBEDDED=1）无并发保护（GPT P2 核实——属实，默认面安全）

**证据**：mcp_server.py `_cli()` 嵌入分支（L30-56）：进程内 `os.chdir(_root())` + `contextlib.redirect_stdout(buf)`，二者均为**进程级全局状态**；无 `threading.Lock`/串行化。FastMCP 工具调用可并发（anyio 线程池），两个并发 tool_run 会互相：① chdir 竞态导致相对路径解析错乱；② redirect_stdout 嵌套/交错导致 JSON 协议串被串话——而 stdout 即 MCP 返回协议体，串话 = Agent 拿到截断/错配 JSON。

**影响面限定**：默认子进程模式（`subprocess.run` 分支）进程隔离，**安全**；嵌入模式需显式 `TBTOOLS_MCP_EMBEDDED=1` 开启，属 opt-in 快路径。故定 P2 非 P1。

**方案（低成本优先）：**
1. 嵌入分支加模块级 `threading.Lock()` 串行化（改动 <10 行，嵌入模式省启动开销的动机本就在非并发场景）；
2. help/docstring 与 RELEASING 文档注明"embedded = 非并发，仅供低延迟顺序调用"；
3. 回归测试：线程池并发 2 个假命令，断言两返回均为完整独立 JSON。

### P3-1：provenance/job 时间戳为本地时区 naive ISO 串

artifact.py:96 `created_at`、cli_top.py job `finished_at` 用 `time.strftime("%Y-%m-%dT%H:%M:%S")`——无时区标记。Agent 跨时区消费 provenance 时无法对齐。修法：`datetime.now(timezone.utc).isoformat()`（"UTC-aware"一项此前宣称已验，实测未覆盖到，属核验口径漏洞，本次补上）。

### P3-2：任务清单口径 vs 实态

"ai/tools 56 manifest"为旧口径，实态 298 个分组目录式 manifest——建议后续自审任务模板以 `find ai/tools -name '*.json' | wc -l` 当前值为准，避免审查官按错口径核验。

## 三、工具成熟度分层（Tier 建议）

按本轮实测 + verification 字段：
- **Tier A（Agent 可直接信赖）**：volcano 等 CONFORMANCE_VERIFIED + fingerprint 齐的绘图命令；tool-run/tool-describe/search 协议面（实测 exit code/JSON envelope 正确）。
- **Tier B（可用但参数面有陷阱）**：muscle/kallisto/findhomolog/iqtree 等线程敏感引擎——功能通，但 `--threads` 静默失效（P1-1 修复前 Agent 不应在 plan 中承诺线程控制）。
- **Tier C（opt-in 风险面）**：MCP embedded 模式（P2-1）、`engine` 反射组（agent policy 默认关，合理）。
建议 manifest 增加 `tier` 字段，把本分层固化为机器可读，Agent plan 时按 Tier A 优先。

## 四、总体结论

发布链（版本单一源/PyPI 1.4.99/manifest 298/meta_guard 守卫/JSON 协议）**健康**；但 Agent 参数面存在**一处实证 P1**：`--threads` 在动态命令与 tool-run 路径被 click 消费后丢弃，muscle/kallisto 等线程敏感引擎静默降级，且 `--runtime-threads` 命名空间修复未闭环（行为分裂）。建议 v1.4.100 前修 P1-1（含回归测试），P2-1 加锁+文档化，P3 时间戳改 UTC-aware。GPT 两项发现均独立实证属实，其中 P1 实际影响面（手写命令契约不诚实 + alias 分裂）大于原描述。
