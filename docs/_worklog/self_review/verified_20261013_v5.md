## 发现

### 🔴 P1-1: 空指纹被当成"同源"——无身份证明继承 CONFORMANCE_VERIFIED(GPT P1 独立确认)

**代码**(`tests/test_conformance_verified.py` L405-408):
```python
_fp_same = (_exec_entries.get(_t, {}).get("contract_fingerprint")
            == _old_entry.get("contract_fingerprint")
            and _exec_entries.get(_t, {}).get("env_fingerprint")
            == _old_entry.get("env_fingerprint"))
```
Python `"" == ""` 为 True。继承路径(L309-323)用 `_o.get("contract_fingerprint", "")` 拷贝旧证据——若旧报告指纹字段为空(损坏/手改/旧格式迁移缺字段),`_exec_entries` 与 `_old_entry` 双侧指纹均为 `""` → `_fp_same=True`。

**探针实证**(核验表 #1): 旧证据 `{level:CONFORMANCE_VERIFIED, contract_fingerprint:"", env_fingerprint:""}` + 金链 skip + Tier2 无 pass → 新报告 volcano 仍为 CONFORMANCE_VERIFIED,`conformance_verified:["volcano"]`。**无契约身份证明也继承了金链等级**,同源守卫形同虚设。

注意:只读校验(L473)要求 `contract_fingerprint` 非空——但那只管**既有报告文件的只读比对**;TBTOOLS_WRITE_REPORT=1 写入路径无此守卫,损坏旧证据会在下一次显式刷新时把空指纹+金链级原样再生产一轮。

**修复建议**(GPT 方向正确,本轮独立同意):
```python
_cfp_cur = _exec_entries.get(_t, {}).get("contract_fingerprint")
_cfp_old = _old_entry.get("contract_fingerprint")
_efp_cur = _exec_entries.get(_t, {}).get("env_fingerprint")
_efp_old = _old_entry.get("env_fingerprint")
_fp_same = bool(_cfp_cur and _cfp_old and _cfp_cur == _cfp_old
                and _efp_cur and _efp_old and _efp_cur == _efp_old)
```
非空守卫:任一侧指纹缺失/为空 → 不同源 → 不继承(降级 EXECUTION_VERIFIED,保守方向正确)。
**回归守卫建议**: TestEvidenceWriteGuard 增用例——旧证据指纹为空 + 金链 skip → 断言不继承 CONFORMANCE_VERIFIED(即本轮探针 1 的测试化)。

### 🟠 P2-1: last_passed_at 混合表示普通执行与 conformance 新鲜度(GPT P1/P2 独立确认,定级 P2)

**代码流**: Tier2 pass → `_exec_entries[_t]["last_passed_at"] = _now_iso`(L352,每次 pass 必刷)→ 金链 skip + 同源继承 → `_verified_tools[_t]["level"] = "CONFORMANCE_VERIFIED"`(L412,**不动 last_passed_at**)。

**探针实证**(核验表 #2): 最终报告 `level=CONFORMANCE_VERIFIED, last_passed_at=2026-10-13(今天)`,但金链今天 skip 未跑。verified_at 保留 2025-06-01(首次验证时间,冻结语义正确),但 last_passed_at 语义是"最近一次 Tier2 执行 pass"——**报告模型没有任何字段表达"最近一次金链 pass"**。消费方(Agent/TTL 检查)读 `level=CONFORMANCE_VERIFIED + last_passed_at=今天` 会误判金链新鲜。

**定级 P2 而非 P1 的理由**: ①现有消费方(TTL `_parse_naive` 判龄、surface/tool-describe)均未按"金链新鲜度"解读 last_passed_at,TTL 用它保鲜 Tier2 执行证据语义自洽;②影响是**决策面误导风险**而非证据错误授予(level 继承本身有 fp 同源守卫背书,P1-1 修复后更稳);③修复成本低但涉及投影面。

**方案**(两选一):
- **A(推荐,低成本)**: 加 `last_conformance_passed_at` 字段——仅 `_gold == "pass"` 时刷新为 now;继承路径保留旧值;fp 变不继承时**不带**旧时间戳(与 level 不继承同政策)。投影到 verified_tools 层即可,TTL/manifest 无需联动(现有消费方不读它)。
- **B(记档)**: 暂不加字段,在报告 `verification_tiers_note` 或 domain_note 明示"last_passed_at=最近 Tier2 执行时间,非金链时间",待有 Agent 消费方真正按金链新鲜度决策时再实现 A。
