### 2.2 评估

- **docs 视角立场**：同意主会话结论——**不新增维度，只澄清边界**。现有五套计数（metadata_commands/readiness/coverage/verification/semantic_checked）已接近认知负荷上限；GPT 矩阵的价值不在维度本身，在「能证明/不能证明」的**边界列**。
- **落点建议（P2，最小改动）**：在 agent-protocol §6.1 末尾或 README L26 四维映射处加一段「指标边界表」，格式：

  | readiness=FULL | 契约五要素齐全 | 参数值域已审计（52/60 unknown）、执行可行 |

## 4. GPT 方法论：四层正确性框架文档化 —— **缺口确认，P3**

GPT 四层：调用正确性 / 产物正确性 / 流程正确性 / 科学正确性，并警告「execution_verified 不应解释为科学分析已验证」。

实测现状：

- **已有边界（环境维）**：protocol §6.1「EXECUTION_VERIFIED 应视为『该版本在该环境跑过』，而非『当前环境可用』」——这是**环境可迁移性**边界，写得很硬。
- **已有边界（语义维，部分）**：§6.1 注明 semantic_checked 11/56 + 「层级≠证据强度超集」——但只说了**数量**，没说**上限**（semantic_checked=true 也不证明生物学结论）。
- **缺口**：全库 grep「科学|生物学结论|正确性」在 README/protocol/readiness **零命中**。没有任何一处声明「我们的验证栈止步于产物正确性，不触及科学正确性」。

**最小文案（P3，与 §2 边界表同点落笔，加两行即可）**：

> **验证层级边界（防过度解读）**：本项目的验证栈覆盖 GPT 四层中的两层——**调用正确性**（tool_validate/exit_code）与**产物正确性**（EXECUTION_VERIFIED + semantic_checked 内容断言）。**流程正确性**（workflow 编排的科学合理性）与**科学正确性**（分析结论的生物学有效性）**不在任何验证维度覆盖范围内**——EXECUTION_VERIFIED 不意味"该分析在你的数据上科学成立"，semantic_checked=true 不意味"生物学结论已证明"。

**定级 P3**：现有 11 条语义断言 + domain_note 机制已经在事实上承认了此边界，文档只是没写出来；误导风险存在但需外部读者（如 GPT）主动高估才触发。
