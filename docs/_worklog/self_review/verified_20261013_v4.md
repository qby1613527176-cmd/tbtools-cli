**P3-2 (死分支)**: `_allow_conf` 升级块 L418 `elif _t in _exec_entries:` **不可达**——`_verified_tools` 由 `_exec_entries` 全量构建(L371 循环), 键集恒等, 第一分支 `if _t in _verified_tools` 已覆盖全部。且该死分支内 `semantic_checked` 用当前静态集合推导(L425), 若未来重构成可达将违反七轮 P1-A(回溯升级)。建议删除该 elif 或改注记明示死代码防护意图。

**P3-3 (语义边界注记, 设计自洽但值得文档化)**:
- A: Tier2 fail + 旧 CONFORMANCE 证据(fp 同源) + 金链 skip/未运行 → **仍继承金链级**(继承条目 fp=旧 fp → `_fp_same=True`)。政策"fail=反观测→降级"仅指金链 fail; 执行层失败不阻断金链继承。方向可论证(金链观测独立于 Tier2), 建议 §6.1 补一句。
- B: 金链 pass + Tier2 fail + 无旧证据 → 工具**整体不进报告**(连 EXECUTION_VERIFIED 也不写, `_exec_entries` 无条目)。保守方向正确(不写无执行证据的条目), 但金链六步通过的痕迹完全丢失, 下次需双 pass 才恢复。探针实证(P1b), 建议文档化。
