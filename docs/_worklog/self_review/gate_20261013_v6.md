### P2-2 env_fp 缓存键 (path,mtime_ns,size) 不识别同大小同 mtime 替换(核实: 属实, 探针实证)
- identity.py:185 `_key = (p, st.st_mtime_ns, st.st_size)`; 探针: 4096B 文件 A→B 替换 + `os.utime` 还原 mtime → **缓存复用旧 SHA-256**(STALE HASH SERVED: True), env_fp 继续指向已不存在的引擎——恰好与该机制要防的场景同构
- 现实性: `cp -p`/`robocopy`/`unzip -DD`(部分工具默认保留 mtime)/手工回滚备份 均可制造; 概率低但后果是"证据链静默绑定旧引擎", 属静默错误而非显式失败
- 方案(按成本排序): ①键加 `st_ctime_ns`(WSL/DrvFs 上 ctime 语义基本可用, 0 依赖, 改一行)——可堵住"写文件必然更新 ctime"的所有常规替换; ②再加 `st_ino`+`st_dev` 更稳(DrvFs inode 语义弱, 需探针验证); ③或提供 `TBTOOLS_ENV_FP_NOCACHE=1` 严格开关供发版/审计场景强制重算 + 文档化局限
- 建议: ①+③组合, 成本最低且留逃生门

### P2-3 多用户 WSL glob 选中字典序靠前用户的 JAR(核实: 属实, 探针实证)
- env.py:63-64 `/mnt/c/Users/*/Downloads|Desktop/TBtools_JRE1.6.jar` → `sorted(glob)` 取第一个 isfile 命中; 探针(Alpha/Zoe 双用户): 恒选 Alpha——**当前用户的 JAR 可能被他人(旧版/损坏)JAR 遮蔽**, 且静默无诊断
- 影响面收窄: 仅回退扫描路径(优先级低于 TBTOOLS_JAR 环境变量/config); 但候选表中 `C:/Users/%USERNAME%/...` 是 Windows 原生路径, **WSL 下没有对应的 `/mnt/c/Users/$USERNAME/...` 精确候选**——WSL 多用户机器上精确路径只能经通配命中, 缺口真实存在
- 方案: 在通配候选**之前**插入 `"/mnt/c/Users/%s/Downloads/TBtools_JRE1.6.jar" % os.environ.get("USERNAME", "")`(用户名非空时)——一行改动, 对齐 Windows 原生腿; 或 glob 命中多个时 doctor 输出候选清单提示歧义
- find_jar_deep()(doctor 深搜)同样 sorted 取首, 但仅诊断展示, 影响更小, 可同方案顺手对齐
