## 二、发现

### P1-1：agent-protocol.md §6 tool-describe 示例与契约自相矛盾（GPT 发现属实，独立复现）

- **证据**：§6 L73 文字声明「**恒返回数组**，单命令/多命令形状一致…单命令取 `[0]`」（八轮 P2-8-① 定案），但紧随其后的 L75-97 示例代码块是**裸 JSON 对象**（`{ "schema_version": "1.0", "id": ... }`，无 `[ ]` 包裹）。实测 `tool-describe volcano --json` 返回 `[{...}]` 数组。
- **影响**：下游 Agent 照示例写解析器（`resp["id"]`）会对真实输出（数组）抛 TypeError/KeyError；文字与示例同屏矛盾，读者无法确定哪个是权威——这正是八轮定案要消灭的歧义，示例没跟上文字。
- **守卫缺口**：test_doc_consistency.py 的 10 项守卫全是数字正则，无任何对文档内 JSON 示例块的结构校验。
- **方案**：
  1. §6 示例改为 `[ { ... } ]`（数组包裹，元素内容不变），与 L73 声明对齐；
  2. §10 Provenance 示例旁注「对象为单条 provenance，非 tool-describe 输出」防串读（可选）；
  3. CI 加结构断言：从 agent-protocol.md 提取 §6 代码块，`json.loads` 后 `assert isinstance(x, list)`——同类「示例 vs 声明」漂移自此有机器拦截（可推广到 §10 provenance 块 assert isinstance dict）。

### P1-2：README_EN 三处与发布状态脱节（GPT 发现属实，且比 GPT 所述多一处）

- **证据**（README_EN.md vs 现状）：
  - L17 `pip install tbtools-cli  # PyPI (v1.3.0 live)` —— PyPI 实际 1.4.97，落后 60+ 个版本；
  - L39-53「Agent Interface (**7 capabilities**)」表格无 Plan 行 —— README.md 已是 **8 阶段**（Discover/Describe/**Plan(workflow-plan)**/Validate/Execute/Observe/Artifact/Provenance）；
  - L25「Requires Java (JRE 1.6 jar)」—— README.md 明确 **JDK 11+（推荐 17），JRE 不够**（javac 编译 118 bridge），英文用户照 JRE 装会在 `tbtools setup`/bridge 编译处踩坑；
  - （附加）全文无 **MCP 9 原语**段落，README.md L131 有。
- **影响**：README_EN 是正式英文用户面；版本号陈旧直接误导安装预期，能力数少一项掩盖了 workflow_plan 决策层（当前差异化卖点），Java 表述错误会导致环境搭建失败。
- **守卫缺口**：test_doc_consistency 只守 README_EN 的 298/RPC/tools/bridges/pitfalls 五个数字，**版本号、能力计数、Java 要求均无守卫**。
- **方案**：
  1. L17 改为生成式/中性表述：`# PyPI (latest)` 或 `# see badge`，消灭手写版本号（版本号单一权威源 = pyproject + badge）；
  2. Agent Interface 表对齐 README.md 8 阶段（补 Plan 行 + Observe/Artifact 语义）；
  3. L25 改为「Requires **JDK 11+** (17 recommended; `javac` needed to compile 118 Java bridges — JRE alone is insufficient), Python 3.10+」；
  4. 补一节 MCP（9 primitives，链 agent-protocol.md）；
  5. CI 守卫扩展：README_EN 禁止出现 `v\d+\.\d+\.\d+ live` 手写版本字面量；能力表行数 == README.md 能力表行数。

### P2-1：命令分类五术语仍缺「不可相加」声明（GPT 建议可采纳，纯文档）

- **现状**：docs/COMMAND_REFERENCE.md 快速导航表已分 5 层（click 298 / tbplot.sh 218 / tool 80 / engine 反射 / RPC 188），命名约定节已有「engine 分组 ≠ 绘图引擎」澄清（八轮成果）。README_EN L5 把五数并列（`200+ plotting + 188 RPC + 80 CLI + 118 bridges + engine reflection`）。
- **缺口**：五层是**投影/重叠关系**（298 注册命令 ⊃ 218 引擎封装 + 80 工具的手写收编；bridges 118 是实现层不是工具），但没有任何一处明说「这些数字**不是互斥工具数，禁止相加**」。新读者（尤其英文面）极易把 200+188+80+118 加成「600+ 工具」。
- **方案（低成本）**：COMMAND_REFERENCE 快速导航表上加一行警告：「⚠️ 五层是同一能力的不同投影（注册/旧入口/工具层/桥实现/RPC），**数字重叠不可相加**；Agent 唯一权威总数 = Registered 298」；README_EN L5 同义改写为 `...engine reflection (layers overlap — 298 registered tools total, see counts.md)`。术语表（Registered command / Plot engine / CLI utility / Bridge / RPC method）可作为 docs/glossary.md 或 COMMAND_REFERENCE 附录，五行即可。
- 评级 P2：不影响正确性，影响首次阅读的认知成本。

### P3-1：agent-protocol.md §10 示例版本字面量 "1.3.0"

- §10 Provenance 示例 `"tbtools_cli": "1.3.0"`（L195）为示意性快照，非契约声明，影响微小；建议在示例上方加「(示例值，实际为运行时版本)」或改 `"<version>"` 占位，与 P1-1 的示例结构断言一并处理。
