## 二、GPT P1-A 的 product 面影响:semantic_checked 继承升级(确认成立,P1)

### 代码事实(verified 链复核)

- `tests/test_conformance_verified.py` L319-327:继承条目(本次 fail/skip/无 JAR 未跑)规整为 details schema 时**只带 6 字段**(contract/env/verified_at/last_passed_at/corpus/domain_note),**故意剥掉 semantic_checked**(52f8b78,L778-781 有守卫断言"继承条目不带 level/semantic_checked")。
- 同文件 L369/L393:写 verified_tools 层时 `semantic_checked` **用当前 SEMANTIC_CHECKS 集合重新求值**(`_t in SEMANTIC_CHECKS`),而非继承旧证据中"当时那次真跑是否做过内容级断言"的事实。
- manifest 投影侧(`gen_metadata.py` L653):`"semantic_checked": bool(_verif_details.get("semantic_checked", False))` —— 直接来自 report 的 `verified_tools[t].semantic_checked` 字段,无独立校验。

### Agent 静态面实测影响

- 当前 11 个 `semantic_checked=true` manifest 中,**peakanno / peaktss 的 last_passed_at=2026-10-06**(本轮 10-12 未真跑,走继承路径),其余 9 个 last_passed_at=2026-10-12(本轮真跑)。
- 即:peakanno/peaktss 的静态面同时呈现 `semantic_checked=true` + 6 天前的 last_passed_at。该 true 标签的语义是"**今天** SEMANTIC_CHECKS 集合里有它",而不是"**产生这份证据的那次运行**做过内容级断言"。
- **误导程度**:若 10-06 之后 SEMANTIC_CHECKS 的断言函数被修改/加强(或工具被移入集合),继承证据会被静默"升级"为带内容级断言——Agent 读 `ai/tools/expr/peakanno.json` 会得出"该证据含基因-链向映射内容断言"的结论,而实际证据产生时可能并未执行该断言。六轮补的 last_passed_at 投影让**细心的** Agent 能发现证据陈旧,但 semantic_checked 标签本身不与证据时间绑定,标签强度仍可超过证据实际。
- nightly writeback 重生成 manifest 会把这个再求值后的标签**自动落盘到静态面**,无需人工过目——自动化放大了标签漂移的传播速度。

### 修复后的验收判据(product 侧)

1. 继承条目的 semantic_checked 必须来自旧证据本身(持久化进 details schema 或 `_o.get("semantic_checked")` 继承),禁止用当前集合再求值;
2. 继承 evidence 的 semantic_checked=false 在无常住真跑 pass 时不得被升为 true(回归守卫);
3. 修复后重跑 render,peakanno/peaktss manifest 的 semantic_checked 与其证据产生时的实际断言一致,且 ai/tools 全量 56 个八字段仍齐全。

## 三、GPT P1-B 的 product 面影响:CONFORMANCE_VERIFIED 静态名单(确认成立,P1)

### 代码事实

- `CONFORMANCE_VERIFIED = {"volcano"}` 是**静态集合**(L250);注释自称"test_conformance.py 金链测试驱动"(L248),但升级逻辑(L371-393)只判断 `volcano ∈ verified_tools`(= 本次 exec pass **或继承旧证据**),**test_conformance.py::test_volcano_golden_chain 六步金链断言的结果未接入升级门禁**——TIER2_RESULTS 只收 conformance_verified 文件的执行结果,金链测试在另一个文件,结果不回传。
- 即:金链测试失败但 Tier2 执行 pass(或旧证据继承)时,静态面照样授 CONFORMANCE_VERIFIED。

### Agent 静态面实测影响

- volcano manifest 当前 level=CONFORMANCE_VERIFIED + domain_note"金链六步断言(格式/sha256/provenance/artifact_id)"+ last_passed_at=2026-10-12。Agent 的自然解读是"六步金链最近一次全过"——但等级实际只保证"exec 层面最近 pass 或继承了旧证据",金链六步是否同步通过**无机器可读绑定**,标签"比实际观测强"的窗口存在。
- 缓解项(已具备,防止误判升级为事故):① domain_note 明示"无内容级语义断言,层级≠证据强度超集"(v1.4.87 P2-8-⑥);② report 层 verification_tiers_note 明示"试验层 n=1";③ last_passed_at 投影后新鲜度可见。这三点把 P1-B 的爆破半径限在"等级 vs 金链结果的绑定缺失",而非全面超卖。

### 修复后的验收判据

1. 金链测试结果(如给 test_volcano_golden_chain 挂结果收集 hook)接入升级条件:金链 fail → 降级 EXECUTION_VERIFIED 或不升级;
2. 守卫测试:模拟"exec pass + 金链 fail"→ report 不得写 CONFORMANCE_VERIFIED;
3. 修复后 volcano 静态面 level 与金链最近结果一致。
