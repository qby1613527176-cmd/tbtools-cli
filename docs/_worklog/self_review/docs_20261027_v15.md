## 一、GPT 审查一 P2-2：validate_artifact 返回层级标注 —— **核实属实，定 P2**

### 现状核实（亲验）

`validate_artifact(path) -> tuple[bool, str]`（executor.py:445）三种语义挤在一个 bool 里：

| 实际语义 | 返回值 | 触发处 |
|:--|:--|:--|
| invalid（解析失败） | `(False, "...")` | 各格式 parse 失败 / file missing / parse error |
| valid（真实解析过） | `(True, "fasta seqs=N" 等)` | fa/gff/nwk/tsv/svg 头部启发式 |
| **unchecked（无解析器放行）** | `(True, "unchecked(.xxx, no parser)")` | executor.py:530 兜底 |

问题链亲验成立：

1. **bool 无法区分 valid 与 unchecked**——下游只看 `_vok` 时，「未校验」与「已验证」同值 True。
2. **层级信息只藏在 detail 字符串前缀**（`unchecked(...)`），下游须做字符串解析才能区分。
3. **真实消费者盘点**（grep 全仓）：
   - `executor.py:216` 工作流内：`_vok` 用于翻转 `step_ok`（unchecked 时 True，不阻断——语义正确但隐式）；
   - `executor.py:230` `_a.metadata["validation"] = _validation_msg or "unchecked"`——Artifact 元数据存的是**裸字符串**，无 status/level 字段；
   - `cli_top.py:1658-1659`（artifact inspect）：`d["validation"] = {"valid": _vok, "detail": _vmsg}`——Agent 可见面同样只有 bool+detail。
4. **协议文档无声明**：`docs/agent-protocol.md` 全文 0 处 "unchecked"（亲验 grep）；§6.2 验证层级边界表只讲 execution_verified/semantic_checked 等宏观层级，未覆盖 Artifact 级 validation 的 valid/unchecked 区分；第 67 行示例 `"validation": {"valid": true, "detail": "svg xml valid"}` 没有 unchecked 样例。

### GPT 建议评估

- **改三态返回值（valid/invalid/unchecked）的兼容影响面**：生产消费点仅 2 处（executor、cli_top），加上 tests/test_validate_artifact.py 14 例——改动面小，技术上可行。但 tuple[bool,str] 是跨模块函数签名，改返回结构属行为变更，需同步协议版本考量。
- **最小方案评估（本人结论）**：**不必改签名**。当前 unchecked 已有机器可辨前缀 `unchecked(`（executor.py:530），真正缺口在**文档面**：
  1. agent-protocol.md §6.2 未声明 Artifact validation 的 valid/unchecked 双层级——Agent 读协议无法得知 `valid=true` 可能是「未校验」；
  2. `metadata.validation` 裸字符串格式（`"unchecked"` vs `"fasta seqs=3"`）无任何文档规范。
- **最小修复**：agent-protocol.md §6.2 补一行层级表项（artifact validation: `detail` 以 `unchecked(` 前缀表示无解析器放行，`valid=true` 不构成已验证语义）+ 示例补 unchecked 样例。代码零改动。

**定级：P2**（Agent 可见语义有误导风险，但有前缀可辨；文档补齐即可消除，不必动 API）。
