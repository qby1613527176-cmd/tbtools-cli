# tbtools-cli v1.4.81 架构/代码 独立批判性审查

- 日期: 2026-10-06
- 视角: 独立架构/代码审查（只找问题，不称赞）
- 范围: v1.4.81 (HEAD eecc0b3) 核心改动 P1-1 —— CommandSpec 唯一运行真源（退 metadata fallback、
  cli.py/auto_commands.py 源码扫描、别名双侧统一、one-step↔onesteptree 环与 build↔_group_of 递归修复）；
  外加对 v1.4.65 arch 审查（arch_review.md）修复点的保持性抽查
- 前置: v1.4.65 审查 P0×1/P1×5/P2×7；本审查聚焦 P1-1 落地质量 + 新增/未闭环项
- 判定: **不通过** — P0 × 1（旧 P0 未闭环，实测复现），P1 × 2，P2 × 6

## 总体结论

P1-1 主体改动**落地是正确的**：`build_command_specs()` 中 command_metadata.json 回退路径已彻底关闭
（全文件仅剩注释提及，无代码路径）；one-step↔onesteptree 互指环修为单向（onesteptree.alias_of=
one-step，反向条目已删）；build↔_group_of↔_spec_groups 无递归（_spec_groups 只读 CATEGORY_MAP
模块属性，不回call）；`import tbtools_cli.command_spec` + `cli_load` 实测正常无挂起；specs 与 metadata
key 集合 298=298，且本次抽查到字段级（dependencies/alias_of/inputs/outputs/output_slots/parameters/
capabilities/relations/named_flags/layout/readiness/verification/dependency_manifest）**零差异**。

但两个维度的"等价"声明不成立：① 上一轮 P0（snapshot_inputs 输出破坏）只对 auto_commands 工厂 impl
闭环，**cli.py 的 ~16 个手写 manual 命令全部不传 output_hint，破坏路径实测仍可复现**；② help 维度上
"真源"比"投影"信息更少（4 个 add_command 别名 spec.doc 为空而 metadata 有借用 help），投影不可由
真源导出——单一真源的方向性承诺在 help 字段上是破的。

## 逐项发现

### N1. 【P0】v1.4.65 F1 未闭环：cli.py manual 命令不传 output_hint，输出回滚破坏实测仍可复现

- **位置**: `tbtools_cli/cli.py`（volcano/heatmap/pca/hclust/dehist/draw/unrooted/rooting/one-step/
  seqlogo/msa/structure/motif/stat_fasta/cds2protein/fasta_extract 等 ~16 处 run_plot/run_java 调用，
  `grep -c output_hint cli.py` = **0**）；`runtime/java.py snapshot_inputs`
- **发现**: v1.4.65 F1 的修复只走了 auto_commands 工厂路径（`_make_impl` 从 doc 解析 `<out...>`
  占位符 → `_out_hint(args)` 传入）。cli.py 手写 manual 命令全部直接调 `run_plot(args, ...,
  command_name=...)` / `run_java(...)`，**无一传 output_hint**。同时 `snapshot_inputs` docstring 声称的
  第二道防线"positional 末位参数且扩展名属已知产物后缀 → 视为输出剔除"**在代码里不存在**——
  `_is_product_path()`（java.py:73）定义后全仓零调用，是死代码；docstring 在描述一个没实现的功能。
- **实测复现**（2026-10-06, tmpdir，v1.4.81 HEAD）:
  ```
  args=[java,-Xmx2g,-cp,build:x.jar,TreeRootingCli,in.nwk,out.nwk]   # out.nwk 已存在(OLD)
  snapshot_inputs → ['in.nwk','out.nwk']        ← 输出照样被快照
  引擎写入 NEW-OUTPUT → verify_and_restore → [('out.nwk','modified-restored')]
  out.nwk 最终内容: OLD-OUTPUT                  ← 新产物被静默回滚(与 v1.4.65 F1 完全相同)
  对照: 传 output_hint='out.nwk' → snaps=['in.nwk'] ✓(修复路径本身是对的)
  volcano 形态(show 后位置输出): snaps=['vol.svg','deg.tsv'] ← 同样中招
  ```
- **挑战**: rooting 是双位置参数（input_nwk output_nwk），volcano 是 show 后位置输出——都是日常
  重跑场景。上一轮的修复声明"snapshot_inputs 输出清理"实际只覆盖了工厂 impl 且依赖 doc 里恰好
  有 `<out...>` 占位符；manual 命令（恰是最高频的绘图命令）全部暴露。docstring 声称的兜底不存在，
  比没有兜底更糟——读代码的人会以为已防护。
- **建议**: ① 接通 `_is_product_path`：positional 值（flag=None）扩展名属 `_PRODUCT_EXT` 且**位于
  任一输入之后**时不纳入快照（或保守：仅末位 positional 跳过）；② cli.py manual 命令逐一把输出
  参数作为 output_hint 传入（它们在调用点都知道输出是哪个变量）；③ 修 docstring 与实现对齐。
- **严重度**: **P0**（静默数据破坏 + 误导性日志，实测复现；旧 P0 未闭环按原标准不降级）

### N2. 【P1】add_command 别名 help 借用未移植到真源：4 个命令 spec.doc 为空，投影比真源信息多

- **位置**: `command_spec.py build_command_specs` 的 add_command 正则分支（doc=""）vs
  `gen_metadata.py scan_manual_commands` step 4（help 借用 `(alias of X) ...`）
- **发现**: 字段级比对实测（298 key 全交集）共 10 处 help 不一致，其中 4 处是真源性缺失：
  `genestructure` / `seqlogo` / `treeRooting` / `heatmap2`——command_spec 侧 add_command 分支
  `doc=""` 不借用目标 help，gen_metadata 侧有借用逻辑。结果：metadata 投影里的 help
  （如 `"(alias of rooting) MAD 系统发育定根"`）**无法从 CommandSpec 导出**——借用逻辑活在投影
  生成器里。P1-1 的方向性承诺（"specs 为唯一输入，投影由真源派生"）在 help 维度被这 4 个命令
  打破；`test_specs_match_metadata` 只比 key 集合，测不出。
- **挑战**: 凡是直接读 spec.doc 的消费方（docs 生成、未来的 spec 驱动 search/describe）对这 4 个
  命令拿到空字符串；且"投影等价"声明实际只是 key 集合等价 + 部分字段等价。
- **建议**: 把 gen_metadata step 4 的 help 借用（fn→命令名映射 + 前缀剥离 + `(alias of X)` 前缀）
  上移进 `build_command_specs` 的 add_command 分支，gen_metadata 删借用逻辑（真源派生）。
- **严重度**: P1

### N3. 【P1】help 截断长度双侧不对称：真源 300 字符 vs 投影 200 字符（6 命令）

- **位置**: `command_spec.py` 扫描正则 `[^"]{0,300}` vs `gen_metadata.py` step 2/3 `[:200]`
- **发现**: bestid/msy/notung/kallisto/mirnatarget/getseqdb 六命令 `spec.help ⊋ metadata.help`
  （投影是真源的前 200 字符截断，实测 prefix-equal + tail 差异）。方向安全（投影⊂真源，不丢真源
  信息），但：① 任何字段级 spec↔metadata 等价检查会在 help 上炸；② 用户经 N33（cli_load 优先
  metadata help）看到的 help 比真源少最多 100 字符——截断点恰好落在各命令的"坑位说明"段
  （bestid 的 threads 注入说明、mirnatarget 的输出不落盘警告、kallisto 的插件 wrapper bug 说明
  都被截掉）。**被截掉的恰恰是坑**，这比长度不一致本身更实际。
- **建议**: 统一为 300（或统一截断策略到投影侧并保证坑位段不落在截断区）。
- **严重度**: P1

### N4. 【P2】KNOWN_TOP_MANUAL 双份拷贝：注释声称"两处共用"，实际各自维护

- **位置**: `command_spec.py KNOWN_TOP_MANUAL`（frozenset，27 项）vs `gen_metadata.py:61-66`
  （inline tuple，内容逐项相同）
- **发现**: command_spec 注释写"与 gen_metadata.scan_manual_commands 排除名单对齐——单一真源下
  两处共用此语义"，但 gen_metadata **没有 import 它**，是两份字面拷贝。新增顶层 Agent 命令时改
  一边漏另一边 → 该命令进一侧模型不进另一侧 → 298=298 破且只有 key 集合测试能抓到（help 等
  字段差异无测试覆盖，见 N2）。
- **建议**: gen_metadata `from tbtools_cli.command_spec import KNOWN_TOP_MANUAL`。
- **严重度**: P2

### N5. 【P2】源码扫描正则脆弱性簇（当前 298=298 是巧合不是保证）

- **位置**: `command_spec.py build_command_specs` 第 3 段 vs `gen_metadata.py scan_manual_commands`
- **发现**:
  1. command_spec 装饰器正则**强制 docstring**（`):\s*"""`）；gen_metadata step 1 只抓名字不要求
     docstring。未来新增无 docstring 的装饰器命令 → 进 metadata 不进 specs → 漂移。
  2. command_spec 只认 `@\w+_group.command`；顶层 `@cli.command` 新命令（不在 27 白名单时）只有
     gen_metadata 的 `@(?:\w+_group|\w+)\.command` 看得见 → 单侧漂移。
  3. 两侧正则的 `[^)]*` 参数段遇默认值含 `)`（如 `def f(x=(1,2))`）即断链，后续命令 doc 错配。
  4. 非贪婪 `[\s\S]*?`：某命令 def 无 docstring 时，正则会越过它把**下一条**命令的 docstring 错配
     给它（两侧同病，不产生两侧差异但产生错 doc；当前无实例）。
- **建议**: 中期把扫描换成 AST（`ast.parse` 一次，decorator/name/docstring 全拿到，消灭整簇）；
  短期至少给 test_specs_match_metadata 加字段级比对（help/kind/group/runner），把"巧合"变"保证"。
- **严重度**: P2

### N6. 【P2】静默降级簇：扫描/分组/别名三路 except-pass，故障不可观测

- **位置**: `command_spec.py` manual 扫描段双层 `except Exception: pass`（cli.py 读不到 → 全部
  manual 命令静默消失，且恰好撞上 N4/N5 时不留痕迹）；`cli_load.py _spec_groups` `except → {}`
  （CommandSpec 分组静默失效退回 CATEGORY_MAP）；`gen_metadata.py` 别名特判的 except 手工 dict
  兜底（异常路径与 spec 投影路径**产出不同结构**，走哪条取决于是否 import 失败——双轨残留）
- **发现**: P1-1 把真源从"读 JSON 文件"换成"读源码+正则"，故障模式从"文件缺失"变成"正则失配/
  读取失败"，而所有失配路径都是静默的。v1.4.65 F10 刚修掉 overlay 的裸 except（现 warn），同类
  病在新增的扫描段又引入了三处。
- **建议**: 扫描段 except 至少 `warnings.warn`（同 F10 修复模式）；gen_metadata 别名手工 dict 兜底
  删除（import 失败就应该 build 失败，不该悄悄降级成结构不同的产物）。
- **严重度**: P2

### N7. 【P2】旧账未闭环（v1.4.65 遗留，非本轮新增）

- **F6 残留**: `executor.py:365` 函数内 `from tbtools_cli.workflow import _topo_sort, plan`——
  self-import `_execute_step` 已除（注释合理化"合理跨层依赖"），但 plan 层↔executor 的反向引用仍在，
  四层拆分未闭合。维持 P1→降 P2 记档（有注释论证，未修）。
- **F7 残留**: `clear_specs_cache()` 已扩展为清三缓存（specs/_SPEC_GROUPS/_META_JSON），但
  **全仓仍零调用点**——死钩子未变，只是钩子变大了。
- **F9 残留**: `command_spec.py:1204` 模块级 `_load_verification_report()` 仍在 import 期全量构建
  specs（实测 import 正常、耗时可接受，但"import 即构建+overlay 比对"的副作用结构未变）。
- **F12-3 残留**: `import tbtools_cli.runtime.java` 作为首模块仍 circular ImportError（本次实测复现；
  已知接受限制，记档）。
- **严重度**: P2

### N8. 【P2】Agent 面直读投影 JSON，无 staleness 守卫

- **位置**: `cli_top.py:617/829/1551` 等 5 处直接 `json.load(command_metadata.json)`（tool-describe/
  xmx 查询等 Agent 面）
- **发现**: P1-1 之后架构宣称"specs 是唯一真源，metadata 是投影"，但 Agent 面读的是投影文件且
  **没有任何 staleness 检查**（对比：YAML contracts 侧有 `_apply_contract_overlay` 快照比对+warn）。
  开发者改 KNOWN_* 未重跑 gen_metadata → Agent 看到旧数据且无任何提示。yaml_to_snapshot 那套
  指纹机制没有延伸到 JSON 投影。
- **建议**: 投影 JSON 头部写 spec 全集指纹（如 `semantic_fingerprint` 的聚合 hash），消费方读取时
  比对并在漂移时 warn。
- **严重度**: P2

### N9. 【P2】_out_hint 位置索引对 flags 交错不稳

- **位置**: `auto_commands.py _make_impl._out_hint`
- **发现**: `_OUT_HINT_IDX` 是 doc `<...>` 占位符的序号，直接拿去索引用户原始 `args`——用户把
  可选 flag 插在位置参数之间（`cmd --threads 8 in.fa out.svg`）时 `args[_OUT_HINT_IDX]` 指向 flag 值
  （不以 `-` 开头，绕过守卫）→ hint 指向错误路径：要么把真输入排除出快照（失去保护），要么
  没排除真输出（N1 场景）。v1.4.65 F1 修复路径自身的边界 bug。
- **建议**: hint 提取改为"从 args 尾部向前找第一个非 flag 值且扩展名命中产物后缀"（与 N1 建议①
  合并实现）。
- **严重度**: P2

## 最值得改的 3 点

1. **N1（P0）**：把 `_is_product_path` 接通为 positional 产物后缀兜底 + cli.py manual 命令补传
   output_hint。上一轮的 P0 修复声明与实际覆盖面不符——工厂 impl 之外的最高频绘图命令（volcano/
   heatmap/rooting/one-step…）全部仍可按"旧输出覆盖新产物"路径静默破坏数据，且 docstring 声称的
   防线不存在。这是"保护机制宣称已修但实际只修了一半"的实锤。
2. **N2+N3（P1）**：help 维度的真源/投影对齐——借用逻辑上移 build_command_specs、截断长度统一。
   否则"投影等价 298=298"只是 key 集合等价；4 个命令投影比真源信息多（方向性破）、6 个命令投影
   截掉的恰好是坑位段（实用性损）。顺手给 test_specs_match_metadata 加字段级比对，把巧合变保证。
3. **N4+N6（P2）**：消灭"声称单一/实际双份"——KNOWN_TOP_MANUAL 改 import 共享、gen_metadata
   别名手工 dict 兜底删除、扫描段 except 改 warn。P1-1 把故障模式从文件缺失换成了正则失配，而
   所有失配路径目前都是静默的。
