## 🟠 裁决三: `--threads` 缺正整数校验 — 属实,P2 确认

**代码事实**:
- `tbtools_cli/cli.py:61-62`: `click.option("--threads", "-t", "--runtime-threads", type=int, default=None, ...)` —— 只有 `type=int`,无范围约束
- `tbtools_cli/cli_load.py:70-81` `thread_args()`: 三态分派(named_flag/positional/unsupported),对数值本身零校验
- 全仓 `grep IntRange`: 仅 `cli_top.py` 交互向导两处用 `click.IntRange`,CLI 选项路径未用

**探针实测**(直接调 `thread_args`):

```
thread_args('muscle', 0)          → (['--threads', '0'], None)   # 0 静默透传
thread_args('muscle', -3)         → (['--threads', '-3'], None)  # 负数静默透传
thread_args('parallelMD5Check', -1) → (['-1'], None)             # 位置槽同样透传
```

即 `--threads 0` / `--threads -1` 不会在 CLI 层报任何错,字面值直达引擎 argv。下游行为取决于各 Java 引擎自身(多数会拒跑或以未定义方式解释),错误被推迟且信息不可控。GPT 指控**属实,定级 P2**(不崩 CLI、不产生错数据,属可用性/防御性校验缺口)。

**修复方案**(供后续轮次采纳,本轮不改代码):
- **首选**: `cli.py` 的 option 改 `type=click.IntRange(min=1)`——click 原生,0/负数/非整数统一在解析层报 `Invalid value`,一行改动,自动覆盖 `-t`/`--runtime-threads` 别名;
- **注意**: `cli_load.py:408` 动态命令构造处(`("--threads", "-t"), {"type": int, ...}`)需同步改,否则静态命令拦了、动态 298 条引擎命令仍漏;
- `thread_args()` 可再加一道 `if threads < 1: raise ValueError` 作为纵深防御(防程序化调用绕过 click 层);
- 配套: 加 1-2 条守卫测试(`--threads 0` → exit≠0 + 报错文案),防回归。
