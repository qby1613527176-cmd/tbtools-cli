## 发现

### P1-1(证实 GPT P1): FULL 就绪等级无法区分「无参数」vs「参数未描述」——独立核实成立

**代码实证**(`command_spec.py:1121-1124`):
```python
params_declared = True  # 恒真——FULL 判定实际只靠 caps/schema/outputs/status
```
注释自承该维度不参与分级,仅 8 工具(volcano/heatmap/hclust/genestructure/dehist/mcscanx/dualsyn/iqtree)有 KNOWN_PARAMS 契约。

**探针实证**(不复述 GPT,独立复算):
- census: FULL=60 / PARTIAL=134 / LEGACY=104(总 298)
- FULL 池中 **52 个 parameters 为空**、8 个有契约——分级对两者给同一标签
- **冒烟枪**: `barplot` usage 自述 `<termCol> <pvalCol> [classCol]`、`circos` 自述 `[w] [h]` ——真实可配置参数存在,但 `parameters=[]` 且 readiness=FULL;与「声明确无参数」的工具(若有)完全不可区分
- 另查实:recipBlast/venn2/venn3/tpmCalc 的 KNOWN_NAMED_FLAGS 均为 input/output 映射而非额外参数,不构成反例;但 barplot/circos/dotplot 等绘图族 w/h 惯例(heatmap 族 8 工具均声明 w/h)证明空列表多为「未描述」而非「确认无参数」

**定级 P1**: readiness 是 Agent 规划信号,维度恒真使 FULL 标签对参数契约零表达力,属标签诚实性缺陷(与十三轮 env 空指纹同类:标签指向未验证事实)。

**方案**(低成本,不铺开):
1. `CommandSpec` 增 `params_status` 四态字段:`complete`(KNOWN_PARAMS 有契约)/`confirmed_none`(人工确认无参数,显式名单)/`partial`/`unknown`(默认,空列表即 unknown,**不得默认为 none**)
2. `agent_readiness` 暂不改分级(避免 60→X 标签地震),但 metadata 注入 `params_status`,Agent 可读;`readiness_census` 附 params_status 分布
3. 后续版本再把 `params_status in {complete, confirmed_none}` 纳入 FULL 判定(渐进,同单一权威退役节奏)
